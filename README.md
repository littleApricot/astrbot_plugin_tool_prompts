# 工具管理

为 AstrBot 4.29.1 提供统一的工具管理页。支持启停插件和 MCP 工具，直接管理内置工具使用的原功能配置，调整模型看到的用途、调用时机和参数填写说明，并统一管理各插件声明内容的上下文位置。

## 安装和打开

在 AstrBot 的插件管理中刷新 littleApricot 共享源，找到“工具管理”并安装：

```text
https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json
```

也可以通过仓库地址安装，或上传 Release 中的 ZIP：

```text
https://github.com/littleApricot/astrbot_plugin_tool_prompts
```

启用后，在插件详情的页面入口打开 `tools`。页面复用 AstrBot 的登录与插件页面桥接。

LCM 的三个历史工具从 LCM v0.6.2 起正式注册，启用后即可按“LCM 上下文与历史”来源筛选并修改。当前的集中管理接口配套 LCM v0.7.0 和本插件 v0.4.0。

## 修改工具说明

a、搜索工具名称、来源或说明，按来源和“全部状态／已启用／已关闭”筛选，也可以同时勾选“只看已修改”。来源选项标出各自的工具数量。左侧列表按启停状态分组，已启用在前、已关闭在底部；关闭工具使用灰色底纹、虚线边框和状态标记。列表展示全部已注册工具，没有 100 项上限，较长时可在列表内滚动。

b、选择工具，修改“工具说明”和下方的“参数说明”。工具说明适合写用途、何时调用、如何理解结果；参数说明适合写填写规则和例子。参数名称、类型、必填规则、默认值和可选值会显示在页面上，执行规则保持原定义。

c、点击“保存说明”。后续模型请求使用修改后的说明，包含同一轮尚未发出的后续请求。已发给模型的请求不会被追溯修改。“预览完整工具定义”可以查看当前编辑内容。

与 LCM v0.7.0 配合时，本插件生成完整工具用法和参数说明，并决定各类声明放在系统区还是临时区；LCM 按结果组装每次实际请求。工具说明进入 `astrbot.tools` 系统块，调用接口保留参数结构、类型、必填规则和约束。工具按名称、参数按键名固定排序，聊天与调用过程不改变说明块。管理页仍是同一个编辑入口，保存后下一次模型请求使用新内容。未启用 LCM 时，说明继续随原生工具定义发送。

工具说明或任意层级的参数说明留空（包括只含空白字符）时，模型收到的工具定义省略对应的 `description` 字段，预览也同步省略。已经保存的空说明更新后直接生效；参数本身及其约束继续保留。

d、点击“恢复默认”移除该工具的自定义说明，使用当前版本提供的原始说明；原文也可以在各字段下展开查看。“只看已修改”便于找回自己的修改。

例如，想让机器人更愿意搜索表情，可以把搜索工具的用途写为：

> 当聊天适合用表情表达情绪时，可主动搜索图库。根据结果决定是否发送；搜索不要求一定发送。

对应查询参数可以写为：

> 结合最近聊天，用简短词描述想表达的情绪、动作或场景。

说明会影响模型对工具的理解，实际调用仍由模型判断。工具内部另一次模型调用所用的任务提示词，继续由对应插件管理。

## 上下文声明与位置

各插件通过 `lcm_context_rules()` 中的 `prompt_blocks` 声明内容，不自行决定集中管理时的放置位置。每个条目包含非空且在本插件内唯一的 `key`、内容类型 `kind`，以及字符串或同步 `event -> str` 的 `content`。外层 `owner` 标明来源；回调组装本地资料，不调用生成模型或发送平台消息，推荐曝光等必要计数按轮次去重。

本插件统一采用下列位置规则，LCM 负责请求组装、历史保存与压缩：

| 声明类型 | 位置 | 判断与整理来源 |
| --- | --- | --- |
| `memory`：人设、偏好、聊天示例、昵称、自我认知 | 系统区 | 判断单独读取；不作为 LCM 历史来源 |
| `notebook_catalog`：记事本目录 | 系统区 | 排除 |
| `tool_guidance`：通用工具用法 | 系统区 | 排除 |
| `tool_definitions`：完整工具用法和参数说明 | 系统区 | 排除 |
| `runtime`：当前时间 | 临时区 | 判断独立提供当前时间；不作为历史来源 |
| `meme_candidates`：表情候选与新增提示 | 临时区 | 排除 |
| `memory_reminder`：主动维护提醒 | 临时区 | 排除 |

未知类型默认放入临时区，仅供正式回复。只在组装对应位置时读取内容，判断读取记忆不会提前生成推荐或累计推荐曝光。同一来源的同位置内容合为一块，按来源及条目标识固定排序。

判断模型的记忆只取 `memory` 声明，不从包含工具说明的完整系统提示词提取。历史投影排除系统消息、带 `_context_kind` 的内部注入消息或片段、临时保存标记，以及消息元数据中的 `tools`、`functions`、`func_tool`；正常聊天、工具调用和结果保留。用户正文中提到工具定义仍属于聊天资料，不按关键词删除。

LCM 后台整理只取得经过上述投影的有效历史，工具定义不参与整理，也不向整理模型提供调用工具。原始档案与实际请求快照继续保留，供用户审计；投影不改写原始档案。记忆插件现有的轮次提醒继续使用，提醒本身不会启动另一套自动整理。

升级时先更新工具管理 v0.4.0，再更新 LCM v0.7.0、回复判断 v0.9.2。记忆与记事本 v0.8.2、群聊表情图库 v0.6.4 补充分类型声明；这是一次接口迁移，之后的位置调整集中在本插件。插件内部标识、仓库地址、数据目录和 `tools` 页面路由沿用原值。未启用本插件时，LCM 使用生产插件的兼容声明，工具说明恢复随原生定义发送。

## 开启与关闭工具

插件和 MCP 工具：选中工具，点击说明编辑区顶部的“关闭工具”或“开启工具”。开关直接使用 AstrBot 原生启停设置并持久化，和原生工具管理页共用状态；重载后仍保留，不改变自定义说明。切换开关会保留正在编辑、尚未保存的说明，并立即调整左侧分组；如果工具不再符合当前筛选，它会从列表移出，编辑区继续显示该工具。

内置工具：先选择页面顶部的“内置工具配置档案”，再选中工具，在“原功能配置”中调整开关或选项，点击“保存原配置”。页面展示该工具的启用条件，可编辑联网搜索与搜索服务、计算机运行环境与沙箱类型、定时任务工具、知识库工具模式、群聊历史记录等原配置项。保存使用 AstrBot 原生配置校验、文件保存与运行流程重载；在原配置页查看的是同一份配置，原页面保存的修改在这里刷新后可见。

一个原配置项可能控制多个工具。例如关闭联网搜索会同时关闭当前服务的搜索和网页提取工具；切换搜索服务会切换对应的一组工具。“共用配置的关联工具”列出联动范围。内置工具的状态分组与筛选按所选档案的原配置条件计算；服务凭证、平台支持、运行环境的实际可用性与权限仍需满足。由平台能力自动提供的 `send_message_to_user` 显示平台条件状态，平台配置继续在原配置页管理。

内置功能配置按档案生效；工具说明、插件和 MCP 的开关仍全局生效。“保存说明”和“保存原配置”分别保存各自内容，并保留另一部分尚未保存的修改。原功能配置在其他页面被改动时，保存会提示刷新并保留当前输入，避免覆盖他人的修改。

所属插件已停用时，请先到插件管理启用插件。同名重复注册的工具会提示使用原生工具管理处理。实际可调用范围继续受人格配置和权限限制。

“群聊表情图库”与旧“表情包管理器”是两个独立来源。前者提供 `meme_search`、`meme_view`、`meme_edit`、`meme_disable`、`meme_send` 五个工具；不要把旧插件的单个 `search_memes` 当成新图库的全部工具。停用工具仍会显示在列表中。

## 保存、更新与生效范围

- 修改全局生效，同一个工具在不同群聊和人格中共用说明。
- 按来源类别、插件名称或 MCP 服务名、工具名分别保存。同名的不同来源工具可以有各自的说明。
- 自定义说明保存在 AstrBot 插件数据目录下的 `astrbot_plugin_tool_prompts/overrides.json`。正常更新并保留插件数据时，说明会保留；备份说明时包含这个文件。插件和 MCP 开关保存在 AstrBot 原生偏好设置中；内置功能配置保存在原配置档案中，随 AstrBot 数据备份。
- 插件更新或 MCP 重连后，同一标识的工具继续使用自定义说明。来源名称或工具名改变会被识别为新工具，旧配置保留在数据文件中。
- 更新导致参数删除时，对应旧参数说明停止应用，页面会提醒；再次保存会清理失效项。“恢复默认”采用升级后的原文。
- 多个页面同时编辑，或编辑期间工具定义发生变化时，保存会提示刷新，避免覆盖其他修改。保存失败保留页面中的文本。
- 停用本插件后，模型请求恢复使用原始工具说明；数据文件保留。

本插件作用于 AstrBot 原生工具定义转换路径，覆盖 OpenAI Chat Completions、Responses、Anthropic、Gemini，以及精简工具模式。外部 Agent 服务若自行维护工具定义，需要在对应服务配置。原生组件列表保留原始说明，自定义内容在本插件页面查看和编辑。

## 本地验证

v0.4.0 的相关隔离检查通过：由本插件位置表统一调整声明位置，判断只读取 memory，后台整理排除系统和内部注入材料，工具使用说明稳定且管理页覆盖生效。还验证了原生工具循环、最终 OpenAI 报文及停用、重新启用后的原数据与路由保留；未调用真实模型、发送 QQ 或修改运行数据。

v0.3.1 与 LCM v0.6.9 配套的离线检查覆盖稳定排序、保存后的说明刷新、嵌套参数说明、调用约束保留及原生 OpenAI 最终报文。提供商传输由内存替身接收，未调用真实模型。

需要 AstrBot 4.29.1 的 Python 依赖环境，以及 pytest、anyio。设置 `PYTHONPATH` 指向 AstrBot 源码和此插件的父目录，然后在插件目录运行：

```sh
python -m pytest tests -q
```

测试使用隔离数据目录，验证说明进入原生提供商请求、工具执行与权限、MCP 调用、精简模式、重载、持久化和恢复默认。提供商请求使用内存 HTTP 传输，不访问真实模型。

启停测试使用 AstrBot 原生 SharedPreferences 与临时 SQLite，验证开关持久化、写入失败时的状态处理，以及停用插件和同名工具的限制。内置功能配置使用临时的原生配置档案与配置保存服务，验证档案范围、原配置页互通、联动、过期编辑保护，以及原生主 Agent 按修改后的配置装载搜索工具；运行流程重载使用隔离回调。

页面测试完整加载超过 100 个工具，操作原配置保存、重新加载、档案切换和说明编辑，验证状态分组、组合筛选、关联工具联动，以及两类未保存输入互相保留。

页面验证使用 `tests/check_page_offline.mjs`，需要 Node.js、Playwright 和测试用 Chrome。配置 `ASTRBOT_SOURCE`、`ASTRBOT_PYTHON`、`PLAYWRIGHT_PACKAGE`；可通过 `TEST_CHROME` 指定可执行文件，再运行：

```sh
node tests/check_page_offline.mjs
```

此脚本使用一次性的无头浏览器会话，并阻断网页网络请求。页面通过子进程管道调用真实插件接口与 AstrBot 扩展路由，不连接 QQ 或用户正在运行的实例。
